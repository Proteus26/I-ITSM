# P3: service catalog, priority, SLA and escalation (minimal)

Code: `backend/src/main/kotlin/com/itsm/{service,settings,priority,sla}`. Migration: `V20261118_1300__service_catalog_and_sla.sql`
(extends the P4 tables `it_services` and `sla_events` with `ALTER TABLE`; adds `sla_policies` and `system_settings`).

## What exists

* **Catalog**: `ItService` (code, name, description, criticality 1-4, owner team, active), 8 seeded services.
  `GET /api/services` (active, any user), `GET/POST /api/admin/services`, `PATCH /api/admin/services/{id}` (admin). Services are deactivated, not deleted. On PATCH, null leaves a field unchanged and an empty string clears `description`/`ownerTeam`. Duplicate code/name is 409, also when concurrent.
* **Priority**: `PriorityService.calculate(PriorityInput)` uses the strategy named by setting `priority.strategy` (default and fallback `weighted`).
  `WeightedScoreStrategy` (`weighted`, thresholds in its KDoc) and `MatrixStrategy` (`matrix`, ITIL table, criticality 4 raises one level).
* **SLA**: `SlaService.computeDeadlines(serviceId, priority, from)` picks the service's policy for that priority, else the default (`service_id is null`).
* **Monitor**: `SlaMonitor.runOnce(now)`, called every `itsm.sla.monitor-interval` ms by `SlaMonitorScheduler` (off when `itsm.sla.monitor-enabled=false`, as in tests).
  Response deadline counts until `acknowledgedAt`, resolution deadline until `resolvedAt`. One `sla_events` row per (incident, type), enforced by a unique constraint.
  There is ONE warning per incident (deliberate, minimal): for whichever window first reaches the policy's warning threshold; the other window gets none.
  The start of each window is derived as deadline minus policy minutes (so deadlines computed from a later `from` are measured correctly). Policies are loaded once per run;
  each incident is checked in its own transaction, and a failure for one is logged without affecting the others.
* **Escalation** (Chain of Responsibility, `sla.escalation`): resolution breach of P1/P2 publishes `IncidentEscalated(level = "ADMIN")`;
  an unacknowledged response breach publishes `IncidentEscalated(level = "REASSIGN_REQUESTED")`. Nothing is reassigned here: P5 picks a technician and P2 applies it.
* **Settings**: `GET /api/admin/settings`, `PUT /api/admin/settings/{key}`; only `priority.strategy` (validated against the registered strategies) and `assignment.strategy` (one of `skill-least-loaded`, `round-robin`; 400 otherwise).

## Contracts for P2 and P5

```kotlin
data class PriorityInput(val impact: Int, val urgency: Int, val serviceCriticality: Int, val affectedUsers: Int, val categoryCode: String?)
data class PriorityResult(val priority: Priority, val score: Double, val explanation: String)
interface PriorityStrategy { val key: String; fun calculate(input: PriorityInput): PriorityResult }
class PriorityService { fun calculate(input: PriorityInput): PriorityResult; val availableStrategies: Set<String> }
data class SlaDeadlines(val responseDueAt: Instant, val resolutionDueAt: Instant, val policyId: Long?)
interface SlaService { fun computeDeadlines(serviceId: Long?, priority: Priority, from: Instant): SlaDeadlines }
class ServiceCatalog { fun criticalityOf(serviceId: Long?): Int; fun listActive(): List<ItService> }
class SettingsService { fun get(key: String, default: String): String; fun set(key: String, value: String) }
```

Typical P2 use: `criticalityOf(incident.serviceId)` and the impact/urgency weights go into `PriorityInput`; store the result with
`incident.applyPriority(...)`, then `incident.applySla(deadlines.responseDueAt, deadlines.resolutionDueAt, now)`.

## How to extend

* New priority strategy: add a `@Component` implementing `PriorityStrategy` with a new `key`; it shows up in `availableStrategies` and the admin setting accepts it.
* New escalation step: subclass `EscalationHandler`, annotate with `@Component` and `@Order(n)`; `EscalationChain` links the handlers in order.
* New setting: add it to `SettingKeys.DEFAULTS` (and validate it in `SettingsAdminService.update` if needed).
