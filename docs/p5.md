# P5: technician assignment and simple smart features (minimal version)

Backend only. Code: `backend/src/main/kotlin/com/itsm/assignment` and `.../intelligence`. Tests: `backend/src/test/kotlin/com/itsm/p5`.

## What exists

| Piece | Class | Notes |
| --- | --- | --- |
| Assignment service | `AssignmentService` | `assign` (configured strategy), `recommend` (ranked, always skill-least-loaded), `availableStrategies` |
| Strategies | `SkillLeastLoadedStrategy` (`skill-least-loaded`), `RoundRobinStrategy` (`round-robin`) | Strategy pattern: add a `@Component` implementing `AssignmentStrategy` |
| Strategy choice | `AssignmentStrategySelector`, `StrategyKeySource` | Key from `itsm.assignment.strategy` (env `ASSIGNMENT_STRATEGY`); unknown key logs a warning and uses the default |
| Admin API | `GET /api/admin/assignment/recommendations?category=&priority=` | ADMIN only; returns `technicianId, technicianName, strategy, reason` |
| Category suggestion | `KeywordCategorySuggester` | keyword lists per seeded category, whole-word matching, only active categories |
| Duplicate detection | `TokenSimilarityDuplicateDetector`, `TextSimilarity` | Jaccard on tokens, title weighted 0.7, threshold 0.3, open incidents of the last 30 days, max 500 rows |
| Intelligence API | `GET /api/intelligence/suggest-category`, `GET /api/intelligence/similar` | any logged-in user; title at most 200, description at most 4000 characters (else 400) |

## Contracts (used by P2's incident service)

```kotlin
data class AssignmentRequest(val incidentId: Long?, val categoryCode: String?, val priority: Priority?)
data class TechnicianCandidate(val id: Long, val fullName: String, val level: String, val skills: Set<String>, val activeIncidents: Long, val maxActiveIncidents: Int)
data class AssignmentResult(val technicianId: Long, val strategy: String, val reason: String)
interface AssignmentStrategy { val key: String; fun pick(request: AssignmentRequest, candidates: List<TechnicianCandidate>): AssignmentResult? }
class AssignmentService { fun assign(request: AssignmentRequest): AssignmentResult?; fun recommend(request: AssignmentRequest, limit: Int = 3): List<AssignmentResult>; val availableStrategies: Set<String> }

data class CategorySuggestion(val code: String, val confidence: Double, val reason: String)
interface CategorySuggester { fun suggest(title: String, description: String): CategorySuggestion? }
data class SimilarIncident(val id: Long, val number: String, val title: String, val status: IncidentStatus, val score: Double)
interface DuplicateDetector { fun findSimilar(title: String, description: String, viewer: AuthenticatedUser, excludeId: Long? = null, limit: Int = 5): List<SimilarIncident> }
```

`assign` only chooses; it never changes the incident. The caller (P2) calls `Incident.assign(technicianId, Actor.SYSTEM, now)` with the result,
or leaves the incident CLASSIFIED when it returns null. Candidates are active, available technicians whose active incident count
(ASSIGNED, ACKNOWLEDGED, IN_PROGRESS, PENDING_INFO) is below `maxActiveIncidents`; the counts come from one grouped query.

## How to extend / what is left

- **Plug in P3 settings**: read `system_settings` key `assignment.strategy` once P3's `SettingsService` exists. Implement `StrategyKeySource`
  (`currentKey()` is called on every assignment) as a `@Primary` bean, or change `PropertyStrategyKeySource`. Keep the property as the default.
- **Recommendation UI**: the admin incident page can call the recommendations endpoint and offer "assign" buttons (the assign action itself belongs to P2).
- **Better ranking**: `recommend` repeats `SkillLeastLoadedStrategy.pick`; give `AssignmentStrategy` a `rank` method if strategies should rank themselves.
- **Round-robin state** is in memory (restart resets it, not shared between instances); persist it if you run several backends.
- **Suggested resolution**: not built. Idea: reuse `TextSimilarity` over RESOLVED incidents and show their `resolutionSummary`.
- **Correlation** of many similar incidents into one problem: not built; the duplicate detector's scores are the starting point.
- **Smarter suggester**: keywords are in `KeywordCategorySuggester.KEYWORDS`; categories created by admins have none. Another `CategorySuggester` bean
  (for example an ML model) can replace it without touching callers. Wire the endpoints into the incident form (P2 / frontend).
