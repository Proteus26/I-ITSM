# P4: events, notifications, audit, search and reports

Everything is laid out for the repo's `backend/` and `frontend/` folders, so it can be copied straight in.
Nothing here has been compiled against the real code (see "Not verified" below), so run `./gradlew build` in `backend/` first.

## Apply it

1. Copy `backend/src/**` and `frontend/**` into the repo. Three frontend files already exist and are **edited, not new**: `frontend/src/lib/backend.ts`, `frontend/src/lib/access.ts` and `frontend/src/components/Nav.astro`. Review those as a diff instead of overwriting blindly.
   In `frontend/`, also run `npm install chart.js` (used by `components/ChartCanvas.astro`).
2. `backend/build.gradle.kts`: add `implementation("org.springframework.boot:spring-boot-starter-mail")`.
3. `backend/src/main/resources/application.yml`: add the block below.
4. Mailpit for the demo: add this service to `docker-compose.yml`, inbox at http://localhost:8025.
   ```yaml
   mailpit:
     image: axllent/mailpit:latest
     ports: ["1025:1025", "8025:8025"]
   ```

```yaml
spring:
  mail:
    host: localhost
    port: 1025                      # Mailpit
    properties:
      mail.smtp.connectiontimeout: 3000   # ms; an unreachable mail server gives up quickly
      mail.smtp.timeout: 5000
      mail.smtp.writetimeout: 5000
itsm:
  frontend-base-url: http://localhost:4321   # used for the links inside emails
  mail:
    gateway: smtp        # smtp -> Mailpit; logging (the default) -> write emails to the log
    from: itsm@example.local
    async: true          # email is sent on a small background pool; tests set this to false
  notifications:
    incident-link: /incidents/{id}   # where a notification points; match the incident detail route
```

### Decision: login audit

`LoginFailed.email` is typed by whoever is at the keyboard, so it is untrusted. Control characters are removed and it is cut to
100 characters before it is stored (as text in `description`; no user id is recorded because the account may not exist). People do
sometimes type a password into the email box, so if that worries you, store only a hash or drop the email and keep just the reason.

## Rules for publishers (P2, P3)

1. Publish `StatusChanged` on **every** status transition; the audit timeline is built from it.
2. Also publish the specific event where one exists (`IncidentAssigned`, `IncidentResolved`, `IncidentClosed`, `IncidentClassified`, `InfoRequested`).
   `RecipientResolver` skips `StatusChanged` for CLASSIFIED / ASSIGNED / RESOLVED / CLOSED so nobody is told twice, so those specific events are what notify people.
3. `actorId` is the user who did it, or `null` for the system.
4. Publish inside the `@Transactional` method. Audit then commits or rolls back with the action; notifications are sent only after commit.

## Definitions

* **Open / active**: `IncidentStatus.OPEN` / `IncidentStatus.ACTIVE`. **Resolved**: RESOLVED, VERIFIED, CLOSED. **Critical**: open P1.
* **SLA breached**: a `RESPONSE_BREACH` or `RESOLUTION_BREACH` row in P3's `sla_events`. **At risk**: open, a `WARNING` row, no breach. **On track**: the rest.
* **SLA compliance**: incidents without a breach / all non-cancelled incidents.
* Dates in search, audit filters and the trend are UTC days (`to` inclusive). Run the database in UTC, or set `hibernate.jdbc.time_zone=UTC`, so the trend's "today" matches.

## Not verified (no compiler here)

These are guesses about code I have not seen. Each is a one-line fix if wrong:

* **P2 `Incident`**: package `com.itsm.incident`; plain id properties `reporterId`, `assigneeId`, `serviceId`, `categoryCode`; `number`, `title`, `description`, `status`, `priority`, `createdAt`, `resolvedAt`; `id` may be nullable. The repository must extend `JpaSpecificationExecutor<Incident>`.
  If it uses relations (`reporter: User`), update `IncidentSpecifications`, `IncidentSearch` and the HQL in `ReportService`.
* **P2 helpers**: `Incident.isVisibleTo(Actor)`, `Actor.of(User)`, `IncidentNotFoundException(id: Long)`, `UnauthorizedOperationException(message: String)`, all in `com.itsm.incident`; `IncidentStatus.OPEN` and `ACTIVE` are collections of statuses.
* **P3**: `com.itsm.sla.Priority`; tables `sla_events(incident_id, type as text, occurred_at)` and `it_services(id, name)` (mapped read-only in `reference/`).
* **Auth events**: `com.itsm.auth.UserLoggedIn(userId: Long, at: Instant)` and `LoginFailed(email: String, reason, at: Instant)`.
* **Tests**: `TestData.incident(...)` builds an `Incident` with named arguments. Adapt that one function to the real constructor. Test configuration (database, profile) is whatever the backend tests already use; I did not add a test `application.yml`.
* The HQL `avg((i.resolvedAt - i.createdAt) by second)` and `cast(... as LocalDate)` need Hibernate 6; they are the two queries most worth running once.
